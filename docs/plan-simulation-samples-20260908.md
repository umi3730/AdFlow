# 按计划生成临时用户样本

## 问题与改动

此前随机池只在固定兴趣、设备、年龄等范围取样，不包含计划自定义标签。演示计划要求 `adflow_demo` / `auction_demo`，因此随机用户可能全部不命中。增加第二种生成方式，不改变原有随机算法，也不修改任何计划、素材和已保存画像。

在“批量投放测试 → 临时用户（不保存）”中选择：

- **随机样本**：原有种子随机算法，不保证满足任何计划。
- **按计划生成样本**：选择已发布规则的参考计划，再选择全部满足、全部不满足或各半。各半模式交替排列满足/不满足用户，奇数时满足样本多一个；只生成 1 人时为满足样本。

生成时重新读取参考计划的已发布版本，处理其自定义标签、`all` / `any` / `none` 和字段的 `eq` / `in` / `gte` / `lte`。生成后自动切换广告位，全选用户；同一规则、组合、人数、种子可复现。更改选项须重新生成。

生成结果显示参考计划及版本、满足/不满足人数，展开列表可查看每位用户的定向预期、标签、设备、年龄和分数。生成时同时读取素材；没有启用素材或计划当前不在投放期会提示，不自动创建素材或修改计划状态。

## 边界

- “满足”仅指满足**生成时所选计划的定向**，不是最终广告命中保证。实际投放仍受素材、预算、频控和竞价限制；不满足该计划的用户可能命中其他计划。
- 生成后若改动参考计划规则，需重新生成。提示中的素材/状态是生成时检查结果，不是持续监控。
- 无法生成要求的样本时明确报错，保留原用户池。例如必须包含且同时排除相同标签、年龄区间矛盾，或无条件计划要求生成反例。
- 定向条件完全覆盖某字段所有合法值时，反例可能通过缺少该字段来构造，不产生越界/非法字段值。
- 临时用户不落库，仍走现有本机模拟接口；生成操作仅读取计划和素材，不发决策、不预占/扣减预算或频控。
- 导出 JSON 的 `context.planSample` 保存参考规则快照、版本、组合、每位用户的定向预期及生成时提醒。原有结果与配置快照保持独立，不被之后编辑覆盖。
- 本次没有修改后端未命中原因归类。无素材仍可能返回 `targeting_miss`；通过生成时的素材提示提前暴露此问题。

## 实现

`web/lib/plan-simulation-profiles.ts` 将匹配/反例需求拆成若干可满足分支。每条条件只依赖一个字段或标签，同一字段内求允许值交集，不枚举全部画像笛卡尔积，也不靠无限随机重试。

枚举字段使用现有字典；年龄枚举 0～120；活跃分数取条件边界和边界间代表值，包含很小的小数区间；自定义文本维持字面值语义。种子确定分支和值选择，未约束属性保留随机分布。输出再次检查规则，拒绝与预期不符的样本。

## 验证记录

2026-09-08 本地验证：

- 前端全部 **117 项测试通过**，新增 10 项生成逻辑测试。
- **3000 个样本**与 Go 的 `domain.Evaluator.Match` 逐条一致，且均通过 Go `schema.ValidateFields`。涵盖中文/演示标签、数值交集、`any` 可行分支、排除条件、小数边界、缺少字段、自定义字符串与特殊字段名。
- TypeScript 类型检查、变更文件格式和 lint 检查通过；前端生产构建通过。
- 合约校验没有调用决策 API，没有数据库写入。这些数量是正确性验证数据，不是吞吐或容量结果。

在仓库根目录用以下命令复跑前后端合约校验（需 Node 24、Go）：

```powershell
New-Item -ItemType Directory -Force work/plan-samples | Out-Null
node tests/plan-sample-contract/generate.mjs work/plan-samples/cases.json
go run ./tests/plan-sample-contract work/plan-samples/cases.json
```

在 `web` 下执行 `npm test`、`npx tsc --noEmit --incremental false`、`npm run build`。

原始测试与构建输出在本地忽略目录 `work/plan-samples/`；可保留、导出或按以上命令重新生成。
