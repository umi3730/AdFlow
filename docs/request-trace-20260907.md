# 单请求处理详情（2026-09-07）

单次测试结果、批量测试的最近结果和事件处理列表新增「查看处理过程」。事件处理页也可手动输入业务 requestId 查询。弹窗可以刷新，打开和刷新都不执行新的决策或事件重放。

## 展示范围

1. **决策**：已保存的用户/广告位、获胜计划及素材 ID、命中原因、成交价、广告主、规则版本和曝光有效期。存在已保存的筛选摘要时可展开查看计数；不重新运行当前规则，也不补造逐个候选的历史判定。
2. **曝光结算**：已受理、等待结算、处理中、已结算或待核对等保存状态，以及已有的时间、失败次数和错误。无广告结果会明确说明无需结算；没有曝光回执不会被说成已经扣费或退款。
3. **事件与计量**：曝光/点击/转化各自的回执、发布状态和计量记录。仅有 PUBLISHED 不表示已计入统计；有匹配的 processed_events 记录才显示已计量。发布回写落后于计量时保留两个状态，不用其中一个覆盖另一个。

时间直接来自现有记录。异步确认回写可能晚于消费，历史版本还可能有应用与数据库时钟偏差，因此不依据这些时间计算严格的阶段耗时，也不改写旧时间来凑出顺序。

入口拒绝、未保存的决策错误或消费错误不一定有持久化明细；弹窗明确说明需结合接口响应和日志。批量请求的客户端错误单独标注为“页面记录”，不冒充服务端事实。需要核对的结算没有自动重新扣费按钮。

## 查询实现

- `GET /v1/operations/request-trace?requestId=...`，沿用 viewer 及以上的只读权限；未登录返回 401。
- MySQL 在只读、可重复读事务中读取执行权、结算和事件状态。查询使用绑定参数、精确请求 ID 比较，最多返回 100 条事件，并明确标记截断。
- 决策从原决策记录或曝光回执中的不可变快照读取，不依赖现有画像或计划名称。
- 计量匹配同时核验事件 ID、请求、计划、素材、类型、金额和发生时间，避免把其他载荷的计量当作当前回执已完成。
- 内存实现只复制本进程已有回执，按 requestId 索引定位事件。单独的 PeekDecision 不触发原 FindDecision 中的过期预留清理。
- 同步模式补充保存实际计量时间和失败确认信息，支持尚未确认的同步回执；没有保存结算确认时间时不补造该时间。
- 查询最多等待两秒。请求尚无记录时返回 404，不断言它没有到达后端；可以稍后刷新。
- 响应不暴露 reservationToken、执行 owner 或 requestFingerprint，也不输出完整用户画像。

## 临时用户模拟

临时模拟在后端用 runId、临时 userId 和原客户端 requestId 生成规范 ID。决策响应成功时直接使用返回的 tmp ID；决策响应超时等情况下，批量链接携带原三元组，后端复用同一纯映射函数定位，避免查询错误 ID 或为查记录重新发起决策。

手动查询应使用测试结果中的业务 requestId，不是 HTTP 日志/请求头的关联 ID。内存模式在重启或记录不再保留后可能无法查询；持久化曝光快照仍存在时可以继续展示历史成交信息。
