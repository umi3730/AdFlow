# AdFlow：第一次上手

帮助统一放在右上角「功能说明」内，也可以从那里准备三轮竞价演示。首页不再展示常驻引导。导航中的「决策调试」「用户池模拟」「运行态」分别更名为「单次投放测试」「批量投放测试」「事件处理」。

AdFlow 用来模拟一套广告投放后台：配置什么广告可以给什么人看，用户到来时选出广告，再接收曝光、点击和转化，最后查看统计。

它目前是供本地演示、验证与学习的系统。广告主是计划上的业务归属，不是独立租户账号；画像是模拟受众，不是后台登录账号。Agent 只辅助配置规则，实际广告选择由 Go 决策引擎完成。

## 各功能做什么

| 页面 | 它回答的问题 | 主要用途 |
| --- | --- | --- |
| 总览 | 已经投放得怎么样？ | 看计划状态和累计曝光、点击、转化价值。 |
| 广告计划 | 什么时候、在哪投、给谁看、愿意花多少钱？ | 配置周期、广告位、定向、预算、出价和频控，并发布版本。 |
| 素材管理 | 最终展示哪张广告？ | 给计划添加图片、标题和落地链接；没有可用素材的计划不能投放。 |
| 用户画像 | 来看广告的是怎样的人？ | 保存模拟用户的标签、设备、活跃分数等属性，用来验证定向。 |
| 单次投放测试 | 这个用户现在能拿到什么广告？ | 发起一次真实决策，看中标计划、价格和原因，并手动回传事件。 |
| 批量投放测试 | 连续来一批用户会怎样？ | 自动执行多轮决策及所选事件回传，看命中、失败和耗时。 |
| 事件处理 | 事件卡在了哪里？ | 排查等待结算、发布、死信和待核对记录；日常演示不必先看这里。 |
| Agent 规则助手 | 不熟悉规则格式时怎样填写？ | 用自然语言生成规则草稿，检查、修改并人工发布。 |

“广告位”是展示位置的标识，例如游戏首页横幅。计划和测试请求必须选择相同广告位，广告才有机会参与选择。

## 先用现成用例走一遍

1. 右上角打开「功能说明」并点击「准备竞价演示」，或打开「批量投放测试」点击「载入竞价用例」。它会读取演示画像，检查计划、周期和素材，把配置设为 3 轮、并发 1，并打开曝光、点击和转化回传。
2. 点击「开始模拟」或「再次运行」。先观察这三轮，不必立即把并发调到 100。
3. 展开结果，看获胜计划和每次成交价。内置示例的出价是 2、5、3 分，正常情况下有效的 5 分计划优先；被修改、暂停、过期、预算不足或频控限制后，结果可能变化。
4. 请求结束后点击「核对统计」，检查最近最多 20 轮中已接收的事件是否计入统计。尚未确认时可稍后重新核对；超过 20 轮的批次不能据此判断整批完成，再到「总览」或效果报表查看累计数据。
5. 若出现失败或统计迟迟不变，再打开「事件处理」查看状态。

单次或批量结果旁可以点击「查看处理过程」，把同一请求的成交结果、曝光结算和计量记录放在一起核对。也可以到「事件处理」粘贴测试结果里的 requestId 查询；刷新详情不会重新投放。

批量页默认收起「自定义用户池」与「高级运行参数」。用自己的画像或生成样本时展开前者；修改最长派发时间、单轮超时时展开后者，当前参数摘要始终可见。未运行时不显示空的耗时和吞吐指标。

页面位置、计划列表搜索与筛选、已提交的报表日期/计划/粒度保存在 URL 中，可以刷新、前进后退或复制链接定位。报表尚未提交的条件不会覆盖 URL。浏览器刷新不会恢复或自动重新启动模拟，临时用户池和表单草稿仍只存在于当前页面会话。

内置用户显示为「竞价演示用户」「基础投放用户」「排除规则用户」「兴趣对照用户」，原始 ID 保留在输入框与画像详情中。名称表示演示用途，不保证命中。兴趣、行为、演示人群标签使用不同样式，悬停可查看含义与标签标识；旧中文标签输入仍可识别。

载入用例只读取已有数据，不会恢复已删除的样例或重置预算、频控。普通演示用例里的「基础投放用户」（`demo-user-match`）如果已经跑到当日频控上限，再次测试仍可能不命中；这不是载入按钮失效。

## 再理解一条完整链路

配置计划和素材 → 选择用户与广告位 → 决策筛选、竞价 → 返回广告并预占资源 → 回传曝光 → 确认预算与频控 → 发布、消费事件 → 更新统计。

点击、转化属于后续行为，可以分别模拟。当前用户池的自动行为会按“曝光 → 点击 → 转化”的顺序执行。

最容易混淆的几个概念：

- **命中不等于曝光。** 决策选出了广告，并不代表用户真的看到了；只运行决策，曝光数不会自动增加。
- **预算预占不等于完成扣费。** 命中时先占住额度，曝光结算时确认。未曝光预留会超时释放；无法证明结算的异常事件进入待核对。
- **事件已接收不等于已计入统计。** Kafka 模式先持久化受理，再结算、投递与消费。
- **用户 ID 区分大小写。** `user-a` 与 `USER-A` 是两位不同的模拟用户，首尾空白会去除。
- **未命中不等于接口失败。** 定向不符、频控已满、预算不足都可以是正常业务结果。
- **转化价值不等于广告花费。** “转化 ¥5”是模拟购买等行为的价值；中标价若为 5 分，则该次曝光按 5 分计价。
- **100 个并发轮次不等于 100 条同时到达服务器的连接。** 浏览器连接排队、网络、决策和事件回传都会进入整轮耗时。

## 自己配置时按这个顺序

1. 在「广告计划」创建草稿，选广告位和周期，填写规则、预算及出价，确认后发布。
2. 在「素材管理」选择该计划，添加并启用至少一个素材。
3. 在「用户画像」保存一个符合规则的模拟用户。
4. 在「单次投放测试」选择该用户及相同广告位，运行一次决策。规则、周期、素材、预算和频控都可能影响结果。
5. 命中后在决策有效期内回传曝光，再测试点击或转化。没有回传曝光就过期时，需要重新发起决策；已有原曝光的点击/转化，可以在该曝光受理后七天内回传。
6. 单次流程确认后再做批量模拟。重复使用保存用户会累计当日频控；临时用户模式可以生成独立的测试身份，但仍会使用计划预算。

## 验证口径

性能数字应同时记录环境、负载和统计范围；浏览器业务模拟不等同于生产容量测试。验证异步流程时，应同时检查事件受理、结算和计量结果。
