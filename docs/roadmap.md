## 已验证的性能范围

当前引用 2026-09-08 的版本化实验：画像热缓存 1000 QPS、单决策 450 QPS、Kafka 完整业务 45 轮/秒。三者是不同负载；失败档位、非零错误与测试窗口见 [README 性能与验证](../README.md#性能与验证)。

100 次新决策尝试/秒的过载保护实验包含明确拒绝，不表示全量接收 100 轮/秒。SQL 索引实验是单语句可见性对照，不表示接口提速同样倍数。最大连接数 30/60/100 对照未支持扩大默认值，保留 30/10；空闲连接 10/20 的探索记录有来源限制，尚未据此更改配置。

## 后续优先项

- **持续依赖维护。** 2026-09-09 已将此前 11 项告警降至完整 audit 为 0，并增加 high/critical CI 门禁。后续仍需跟进公告和兼容回归，适时移除针对 Miniflare 的 Sharp 临时 override；见[升级记录](dependency-maintenance-20260909.md)。

1. **可复现基础设施测试。** 增加独立的 CI integration job，自动准备空库、Redis、Kafka Topic，确保没有跳过测试，并保存结果和清理状态。
2. **更长故障与多实例验证。** 补充持续依赖中断、broker 分区调整、租约跨期、晚到曝光、多 API 同时过载等受控场景，核对最终金额、事件和恢复时间。
3. **对账与保留策略。** 定义 RECONCILE 的人工核对、操作审计和恢复边界，以及 decisions、receipts、processed events、死信的归档和保留规则。
4. **按证据优化数据库写入。** 继续分析结算和同步审计的提交开销；任何批量化、调度或并行度调整都先固定正确性与对照条件，再决定是否采用。

## 按需要推进

- 按页面和业务 Hook 拆分前端主组件，增加真实交互测试，进一步收拢状态与刷新依赖。
- 批量测试高级参数折叠、计划复制/期限编辑、规则版本比较，以及更清晰的 Agent 小样本建议分层。
- 选择时序存储后补充长期指标趋势和告警；当前实例快照不等于监控平台。
- 有生产接入需求时再增加外部身份、令牌轮换、严格审计事务或广告主隔离。当前默认免登录演示行为保持不变。

不把这些待办写成已经具备的生产保证，也不为增加组件数量而拆分服务。新增工作仍按“动机 → 实现 → 验证 → 对应版本”归档。
