# 核心画像字段约束

## 存储事实

建表脚本 `migrations/000004_profiles.up.sql` 定义 `user_profiles(user_id, tags JSON, fields JSON, updated_at)`。设备、分数、国家等是 `fields` 中的键，不是独立 SQL 列。上一轮添加 UI 候选并没有新增这些数据库列。

本次不迁移、不清洗已有 JSON，也不删除旧标签和字段。字段约束属于应用层逻辑类型；字段值仍按现有接口以字符串存储。

## 当前范围

- 固定为 5 个通用字段：device（设备）、score（活跃分数）、age（年龄）、member_level（会员等级）、channel（来源渠道）；5 个标签：tech_interest（数码兴趣）、gaming_interest（游戏兴趣）、active_7d、new_user、paying_user。购物兴趣不再推荐，但已有 shopping_interest 数据保留原义。
- device 只支持等于/属于，值为 android、ios、windows、macos、web。
- score 支持等于/属于/大于等于/小于等于，值必须为 0～100 的有限十进制数。NaN、Infinity、科学计数法和空集合成员拒绝。
- age 必须为 0～120 的整数，支持等于/属于/大于等于/小于等于；年龄范围通过两条条件表达。
- member_level 只接受 basic/silver/gold/diamond（普通/白银/黄金/钻石会员）；channel 只接受 organic/paid/referral（自然访问/广告投放/邀请推荐）。二者只支持等于/属于，不能按等级名称排序。规则编辑中“属于”提供字典多选。
- 国家/地区不再推荐；旧 country、region 和游戏标签不自动删除或改义。未知旧字段仍按文本处理，不能大小比较；已有非法字典值需人工修正后再保存。
- 非上述五项的旧画像扩展字段折叠显示，不再提供无限添加字段的入口。已保存的扩展标签不强制清除。

## 校验与兼容

- 前端通过字段决定操作符与输入控件；切换字段重置操作符和值。
- 画像 PUT、领域发布/恢复、Agent 草稿校验均采用对应类型规则。绕过前端直接提交 country >= 156 返回 422。
- 历史规则反序列化仍保留旧形状校验，避免单个旧规则导致整个计划列表读不出来；新发布和恢复必须满足新约束。
- 决策求值对无效历史比较采取 fail-closed，包含 ANY/NONE，防止错误排除条件反而扩大人群。诊断返回 invalid_condition。
- score 的等于/属于按数字语义判断，如 88 与 88.0 相等，不误用字符串比较。
- Agent 提示词升为 v8，与通用字段、标签和字典同步，默认需求为数码/游戏场景；本地关键词解析同步兴趣 OR 和新用户/付费用户标签，但年龄、会员等级、渠道仍明确警告需要手动补充。购物、二次元等旧标签按原义兼容。提示词不能取代服务端校验。

## 控件

规则类型、标签、字段、操作符和设备选择使用现有 Base UI / shadcn Select，替换浏览器原生 datalist 弹层。菜单沿用页面颜色、字体、圆角和固定最大高度，支持键盘与禁用状态。旧未知值显式标为「已有值」，不偷偷替换。
