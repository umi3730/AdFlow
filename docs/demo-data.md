# 内置演示用例

## 安装与删除规则

API 默认开启 `ADFLOW_DEMO_DATA=true`，可设为 `false` 关闭。初始化在 HTTP 接收请求前完成，不依赖访问某个前端页面。

- 内存仓储：新进程创建一套。当前进程内可修改、暂停、禁用和删除；不自动修复。重启内存服务是新环境，会重新带一套。
- MySQL：先运行 `go run ./cmd/migrate -dir migrations`，应用 `000007_demo_data`。首次开启时安装，以 `bootstrap_seeds` 保存完成标记；以后部署/重启跳过，用户删除后不恢复。
- 支持混合仓储：计划及素材、画像分别记录初始化状态，持久数据不因另一组使用内存而被重建。
- MySQL 每组数据与完成标记处于同一事务；唯一键和行锁串行处理并发启动。保留 ID 冲突会失败，不覆盖用户数据。任一组失败会阻止本次 API 启动，重试继续未完成的组。
- `mysql-redis` 模式只失效三个演示画像的缓存键，以防此前负缓存遮住新数据；不清空整个 Redis。

首次在已有数据库上启用时也会安装这套独立记录；“一次”以种子标记为准。不要删除标记表来恢复样例，这会造成已有资源 ID 冲突。性能基准环境可关闭演示初始化，并使用独立压测数据。

## 自带内容

| 类型 | ID | 内容 |
| --- | --- | --- |
| 计划 | `demo-campaign-v1` | 演示计划 · 游戏首页；广告位 `game-home-banner`；已发布，截止 2099-12-31 UTC |
| 素材 | `demo-creative-v1` | 本地素材库中的千早爱音图片，落地页为 `https://example.com/game` |
| 命中画像 | `demo-user-match` | 含 `adflow_demo` 标签，默认满足计划 |
| 排除画像 | `demo-user-excluded` | 同时含 `adflow_demo` 和 `demo_excluded`，默认被排除 |
| 不匹配画像 | `demo-user-miss` | 不含 `adflow_demo`，默认不满足定向 |

预算 ¥100/日，单次曝光 ¥0.01，每个用户每天最多 100 次。只向带演示标签且不被排除的用户命中；默认临时池不带演示标签，不会被该计划随意截获。频控、预算、候选缓存、事件顺序和权限均使用正常业务逻辑。

没有预填曝光、点击、转化或性能数据。反复测试达到频控/预算后仍会正常拒绝，不能将演示用例视为无限额度通道。修改或新增其他计划后，以实际数据为准。

素材在后端使用固定标识 URL `https://adflow.invalid/demo-assets/bangdream/anon.webp`。前端仅将此保留 origin 下已登记的素材映射到当前站点的资源路径，不请求该域名，也不硬编码 localhost；其他 URL 不改写。

## 使用

1. 在广告计划、素材管理、用户画像页可看到和编辑这些普通资源。
2. 决策调试选择 `demo-user-match` 和「游戏首页横幅」，运行后依次记录曝光、点击、转化。
3. 用户池模拟点击「载入演示用例」：只读取仍存在的三个画像，配置少量并发与轮数，点击开始后才发出请求；不会恢复被删除的样例。
4. 全新、未修改环境的一次三人运行应有 1 次命中、2 次未命中；命中用户完成曝光→点击→¥5 转化。失败原因和最终计数按实际响应展示。
5. 删除演示计划前先暂停；素材和画像沿用现有管理员删除入口，无不可删除保护。

## 回归证据

`internal/bootstrap` 测试覆盖三种定向结果、完整事件链、零初始统计、重复安装保留修改与删除、内存重启、保留 ID 冲突、并发初始化、事务失败回滚及混合仓储状态。MySQL 事务测试使用 sqlmock；本轮不声称已验证真实 MySQL 并发启动。

前端 `demo-data.test.mjs` 覆盖只读载入、删除不恢复、读取失败不伪装成删除，以及跨部署素材路径解析。`decision-events.test.mjs` 验证调试回传的同步互斥、稳定重试 ID、曝光前置与跨决策隔离。所有前端测试由 `npm test` 自动发现并进入 CI。

2026-09-07 本地验证：确认原内存服务无计划和画像后启动新版，自动得到 1 条 ACTIVE 计划、1 份素材和 3 个画像，初始指标均为 0。浏览器「载入演示用例」完成 3 轮：1 次命中、2 次未命中、1 次曝光/点击/转化（¥5），共 6 次 HTTP 调用，失败和取消均为 0。素材正常显示；另一次手动决策验证了曝光前点击/转化禁用，以及成功曝光后「曝光已记录」禁用。预览中留下的是这些实际测试计数。

Go 全包测试与 vet、88 项前端测试、类型检查、lint、前端构建通过。本机未启用 CGO 且没有 C 编译器，未运行 race 检测；CI 的 Linux Go job 继续执行 `go test -race`。本轮未连接真实 MySQL 运行初始化事务，不把 sqlmock 等同于真实数据库并发验收。
