# 五分钟演示 AdFlow

目标：用一次实际投放讲清规则、竞价、扣费和异步统计。页面数字是模拟数据，截图不是压测证据。

## 演示前准备

- 启动 API 和前端，确认右上角显示 API 已连接。默认免登录进入管理员工作台。
- 使用右上角「功能说明 → 准备竞价演示」，或批量投放页的「载入竞价用例」。载入只检查和选择已有数据，不恢复删除的样例、不重置预算和频控。
- 检查竞价示例的三个计划已发布、有启用素材且处于投放时间内。缺素材时会明确显示「待添加素材」。
- 内存模式可以体验功能；要展示真实 Kafka 发布和消费过程，使用配置好的 MySQL/Redis/Kafka 模式。不要把两种运行方式混着介绍。

## 现场流程

| 时间 | 操作 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:40 | 打开总览，再进入广告计划 | 广告位决定展示位置，画像决定给谁看；后台管理员和模拟用户是两种对象。 |
| 0:40–1:30 | 查看竞价演示规则 | 三家出价 2、5、3 分；同一家按广告主编号选代表计划，符合条件且预算/频控允许时优先选择高价；一价竞价按自身出价计费。 |
| 1:30–2:30 | 运行已载入的三轮竞价示例 | 确认广告命中、成交价，以及曝光/点击/转化受理数。少量轮次用于看懂功能，不拿浏览器结果当后端最大 QPS。 |
| 2:30–3:30 | 点击结果的「查看处理过程」 | 决策先预占预算；曝光结算后确认花费。区分已受理、结算、发布、已计入统计，说明幂等为何重要。 |
| 3:30–4:30 | 进入效果报表，选择今天与中标计划 | 对照曝光、点击、转化、消耗和转化价值。明细默认收起，可按需展开；修改筛选后再查询，快捷日期会直接查询。 |
| 4:30–5:00 | 打开性能与验证记录 | 展示 SQL 索引对照、完整链路容量和过载保护三个结论，说明测试条件；有余量再演示 Agent 的辅助分析。 |

## 常见情况怎样解释

- **没有中标：** 先看未命中原因，再看当前配置检查。未发布、没有素材、标签不符、频控或预算不足分别处理；不要为了演示成功直接绕过业务限制。
- **提示频控或预算不足：** 旧用户的已发生曝光会累计。载入用例不是重置；需要新场景时新建明确命名的演示计划和画像，不删除已有账目。
- **金额和转化价值不同：** 曝光按成交价收费；模拟转化 ¥5 表示转化价值，不代表花了 ¥5。
- **HTTP 已受理但报表未变化：** 检查同一请求的结算和计量状态。Kafka lag=0 也不能代替上游完整核账。
- **只想稳定展示：** Agent 可用默认 mock。模型不可用不影响确定性的广告决策；不要临时填写或展示 API 密钥。

结束后暂停临时创建的演示计划，保留请求记录便于解释。完整功能关系见 [第一次上手](getting-started.md)，可引用数字见 [面试与简历要点](resume-and-interview.md)。
