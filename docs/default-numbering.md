# 默认编号修复 · 2026-09-04

## 问题

计划、素材、用户各自读取并累加 localStorage 中的历史序号。内存后端重启或数据删除后，这些计数没有重置，于是空库也从 019 等历史数字开始。

## 当前行为

- 计划：按当前全部未删除计划，选择最小未占用正整数，格式为“测试计划 001”。019、020 已存在但 001 空缺时，下次默认 001；原计划不改名。
- 素材：按当前选中计划的未删除素材，格式为“测试素材 001”；不同计划不再共用浏览器计数。
- 用户：按不带筛选条件的全局画像目录，选择最小未占用 user-0001 编号；翻页、筛选、临时模拟用户不影响它。
- 三者不再读取/写入历史序号缓存；空数据集从 1 开始，删除造成的空号可以复用。用户手动输入的名称/ID 优先，不自动覆盖。
- 成功保存后先把服务端返回的数据并入当前目录，再刷新；失败不消耗编号。编号相关列表未加载完成或读取失败时禁止对应保存，避免按不完整数据猜号。
- 计划/用户目录扫描分页，不能只看第一页。该逻辑是演示表单默认值，不是服务端主键分配或跨客户端原子号段；用户保存仍保留存在性检查。既有数据库 ID、审计记录、频控及历史事件不修改。

## 验证

- 75 项前端测试通过，覆盖空库、019/020 历史高号、间隙、重复/自定义名称、跨 205 条记录分页、分页失败、全局画像目录及旧缓存不再引用。
- lint、类型检查及生产构建验证。
- 只读核对当前后端：计划 019/020 -> 默认计划 001；两计划均无素材 -> 素材 001；正式画像 0 条 -> user-0001。
- 后端未重启，未修改/删除任何当前计划、素材、画像；未进行浏览器点击验收。
