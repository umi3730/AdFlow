## 模块边界

- `components/adflow-console.tsx`：导航、权限、跨页选择、通知和页面组合。
- `components/console/dashboard.tsx`：默认立即加载的总览。
- `components/console/campaigns-view.tsx`：计划列表、创建和规则编辑入口。
- `components/console/creatives-view.tsx`：素材创建、选择和管理。
- `components/console/decision-view.tsx`：单次投放、事件回传和定向解释。
- `components/console/operations-view.tsx`：事件处理、积压、回放和 Kafka 状态。
- `components/console/shared.tsx`：计划表格、指标卡片、状态和表单基础布局。
- `hooks/use-console-data.ts`：计划与指标刷新、并发刷新合并。
- `components/report-filters.tsx`：报表与诊断共用筛选器，避免诊断页通过筛选器导入整套图表。

## 加载与状态

工作页使用 React.lazy，并各自拥有 Suspense 边界。这样一个页面加载时，不会让其他已挂载页面一起进入挂起状态。

素材、单次投放和批量投放在首次进入后保留挂载，切换页面只隐藏它们。尚未进入时，不加载这些页面的代码。批量投放保留全局停止、离开页面继续执行、有限时长统计刷新及原有卸载取消逻辑。

跨页选择的素材计划、单次投放用户和广告位由控制台拥有。普通导航保留输入和历史结果；明确从计划或画像发起新的测试时，用独立选择修订号重建测试会话。旧会话的清理逻辑继续使旧响应失效并取消事件控制器，用户与广告位输入由父级保留。

去掉三处依靠 effect 将导航参数复制到本地状态的代码，避免额外同步更新。数据刷新提取为 Hook 后，编译器能识别其依赖；取消重复的首次加载 effect，由总览/计划视图的刷新入口负责发起加载。

刷新逻辑保留“一次在途刷新、后续合并排队”的行为。素材读取失败仍标记为未知状态，不把错误当成零素材；失败刷新会释放在途标记，允许后续恢复。

## 复查命令

在 `web/` 下运行 `npm run build`，然后回到仓库根目录：

~~~powershell
node scripts/inspect-client-bundle.mjs
./scripts/verify.ps1
~~~

分析脚本读取实际产物清单，输出控制台分块、立即加载依赖、最大分块与 gzip 大小。不会更改源码、阈值或发布站点。
