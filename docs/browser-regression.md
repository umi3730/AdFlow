# 自动化浏览器功能回归

## 运行

需要项目要求的 Go、Node.js，以及 Playwright Chromium。首次准备：

~~~powershell
cd web
npm ci
npx playwright install chromium
npm run test:e2e
~~~

Linux CI 使用 `npx playwright install --with-deps chromium` 安装浏览器和系统依赖。后续无需重复安装浏览器；Playwright 版本变更时重新执行安装。

仅运行一个尺寸或筛选用例：

~~~powershell
npm run test:e2e -- --project=desktop
npm run test:e2e -- --project=mobile
npm run test:e2e -- --grep "global stop"
npm run test:e2e:report
~~~

仓库根目录也可使用 `./scripts/verify.ps1 -Browser`，依次执行常规 Go/前端检查和浏览器回归；`make browser-test` 单独运行浏览器用例。默认 `npm test` 与 `scripts/verify.ps1` 仍保留快速检查路径。

## 覆盖

9 个业务用例分别运行于 1280×800 桌面和 390×844 窄屏，共 18 项：

| 用例 | 关键断言 |
| --- | --- |
| 完整投放与报表 | UI 创建和发布计划、无素材原因、素材草稿跨页保留、保存画像、用户/广告位带入、新测试清除旧结果、曝光/点击/转化、请求追踪、报表日期校验和 CSV 文件内容 |
| 曝光过期 | 在页面隐藏期间推进浏览器时钟；返回后仍保留原请求，曝光按钮自动禁用，服务端没有新增曝光 |
| 有限批量运行 | 3 轮、并发 1；正常完成、无失败/超时，切页返回后结果保留；核对真实计量记录，新批次清除旧确认结果 |
| 全局停止 | 等待真实决策响应后暂缓交付浏览器；切到总览仍能停止，取消 1 轮、在途归零且没有继续派发 |
| 成交计划与其他候选 | 成交计划单独标记；未满足定向的其他计划默认折叠，展开后明确说明未成交，不与成交计划的条件混淆 |
| 中文用户名称与标签 | 选择框、画像列表、批量用户池统一中文演示名称；保留实际用户 ID、自定义标识和标签说明 |
| 规则中的已有标签 | 查看和编辑已发布规则时，演示标签显示中文；重新发布后仍保存原始标签 ID |
| 页面与计划筛选恢复 | 刷新、前进后退恢复工作区、搜索和筛选；高级参数默认折叠，刷新不启动模拟 |
| 报表链接与历史 | 仅已提交的日期进入 URL；直接链接、刷新及后退恢复对应查询 |

完整业务用例通过浏览器下载 CSV 并读取文件校验内容。它确认的是独立 Chromium 的下载路径，不代表 Codex 内置浏览器的下载能力已经修复。

候选缓存保留默认 TTL。补素材后的新请求使用有界断言轮询等待生效，不使用固定长时间休眠，也不修改生产缓存参数。其余用例使用不同广告位，避免前一个用例的候选缓存影响下一个用例。

## 隔离与生命周期

- 后端固定为 `127.0.0.1:18082`，使用真实 Go 程序的内存适配器、同步事件链路和 mock Agent；不加载仓库 `.env`。
- 启动环境移除已有 `ADFLOW_*`、`NEXT_PUBLIC_*`、Vinext/Wrangler/Miniflare 配置和 Node 预加载参数，再显式设定测试配置。
- 前端固定为 `127.0.0.1:4173`，复制当前应用源码至独立临时目录；仅复用依赖安装，Vite 缓存、Vinext 锁、Wrangler 文件均留在副本内。
- 前端通过同源代理访问测试后端；测试阻止浏览器请求其他来源。日常的 3001、18080、18081 环境不会被复用或清空。
- 两个测试端口只要被占用就拒绝启动，不自动连接既有服务，也不自动换端口。
- 每个用例创建独立计划和用户，并清理自己创建的资源。整个后端进程退出后，内存测试数据消失。
- `npm run test:e2e` 在测试完成、服务退出后清理本次临时目录；删除前检查绝对路径范围，并先移除依赖目录链接。
- 常规中断或强制终止可能留下 `web/work/e2e/` 中的临时副本。不要在测试仍运行时手工删除这些目录。

这套测试验证 UI 与真实 Go 内存实现的协作，不替代 MySQL/Redis/Kafka 持久化恢复、真实模型服务或性能压力测试。浏览器时钟只用于 UI 过期边界；停止用例只控制响应交付时机，不伪造后端决策结果。

## 结果与故障定位

- HTML 报告：`web/playwright-report/`。
- 失败截图、trace 与下载文件：`web/test-results/`。
- 报告和临时目录均已加入忽略规则，不提交生成内容。
- 出现失败时，先看报告中的断言、页面快照与 trace；不要通过取消断言、关闭检查或盲目增加重试掩盖问题。
- CI 独立运行浏览器任务，无需 MySQL、Redis 或 Kafka；无论成功或失败都尝试上传测试报告，保留 7 天。

实现位于 `web/playwright.config.ts` 与 `web/e2e/`。服务自动管理遵循 [Playwright webServer](https://playwright.dev/docs/test-webserver)，过期边界使用 [Playwright Clock](https://playwright.dev/docs/clock)。
