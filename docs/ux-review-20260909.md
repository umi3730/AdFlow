## 优先改的问题

### P1：发布成功和“可以投放”没有区分

复现：不添加素材就发布计划，列表和规则弹窗均显示「投放中」。只有实际测试未命中，才在下方定向检查中发现没有有效素材。创建后也没有直接补素材或试投的入口。

建议保留规则可先发布的能力，但状态明确显示「已发布 · 待添加素材」，并提供「添加素材 → 测试此计划」。无有效素材时不计入“可投放计划”数量。发布前确认列出缺失项，不让用户依靠失败测试发现必需步骤。

验收：从零创建计划，用户不看帮助也能知道是否还缺素材、下一步在哪里；操作入口带入当前计划和广告位。

### P1：未命中原因会互相矛盾

复现：计划只要求数码兴趣，选择具有该标签的用户。没有素材时，结果标题是「用户未满足定向条件」，同一页下方显示「定向条件满足」「该计划没有有效素材」。

代码线索：[候选排序](../internal/decision/application/auction.go#L34) 会过滤没有素材的候选；[决策服务](../internal/decision/application/service.go#L128) 默认使用 targeting_miss，[前端](../web/components/adflow-console.tsx#L1854) 将它翻译成定向失败。

建议修正服务端筛选原因，区分没有可用素材、定向不符、频控、预算等；主结果给出可行动的原因，并链接到对应计划。保留“当前检查”和“历史决策”的时间区别，不能拿当前配置覆盖历史原因。

验收：上述案例明确显示缺少素材；真实标签不匹配案例仍显示定向不符，已保存历史原因不被重新解释成别的事实。

### P2：跨页面操作丢失上下文

复现：单次投放选好用户和活动弹窗，去素材管理补素材，再返回，用户 ID、广告位、原结果全部清空。素材页也未继承刚创建的计划；查看报表要重新找到计划。

代码线索：[按 view 条件挂载页面](../web/components/adflow-console.tsx#L590)，[单次投放内部状态](../web/components/adflow-console.tsx#L1479) 随组件卸载丢失。

建议用会话级状态保留表单与最近测试；增加带参数的「添加素材」「测试此计划」「查看本次报表」。返回旧结果时仍按原有效期控制曝光按钮，不延长决策有效期、不自动重发。

验收：同一会话中去补素材再回来，用户/广告位仍在；测试结果能按明确按钮主动重置。

### P2：成功通知过期后仍占据其他页面

复现：发布已经成功，顶部仍显示「计划草稿已创建，尚未投放」；切换到投放测试也保留这条通知。之后「转化事件已受理」继续出现在画像、批量和 Agent 页面。

代码线索：[全局 notice](../web/components/adflow-console.tsx#L188) 与[规则弹窗内 success](../web/components/campaign-rule-dialog.tsx#L133) 是两套反馈。

建议成功通知自动消失或随操作阶段替换，局部反馈留在操作附近；错误与未保存内容仍应保留到用户处理。跨页面不携带已失效的任务提示。

验收：创建→发布后不再出现“尚未投放”；进入无关页面不显示上一页的成功横幅。

### P2：异步成功后缺少统计更新闭环

复现：两轮批量曝光均已受理，稍后回计划列表仍是 1 次曝光，手动刷新才成为 3 次。单次投放主结果也始终停留在“已受理”，需要另开处理过程才能确认计入统计。

代码线索：批量页会在运行完成后调用 [onFinished](../web/components/user-pool-simulation.tsx#L452) 刷新，但 HTTP 受理结束可能早于统计落库，因此一次刷新仍可能读到旧值。

建议在完成回传后显示「已受理，统计更新中」，进行有次数/时长上限的状态刷新；计量完成后更新相关计划和总览，或在返回页面时校验数据新鲜度。超时显示继续查看处理过程的入口，不能直接当成业务失败，也不能无限轮询。

验收：故意延迟后台消费，页面先显示更新中，随后自动变为最终数量；无需用户猜哪个刷新按钮有效。

### P2：窄表格中固定操作列遮挤信息

复现：1280px 桌面下画像列表与右侧表单并排，列表已需要横向滚动，设备文本被挤到边缘；390px 下三个操作按钮占据大部分行宽，用户 ID 只剩开头，标签/设备无法同时看到。

代码线索：[画像布局与表格](../web/components/profile-workspace.tsx#L227) 使用固定右侧表单和 650px 最小表宽，[操作列](../web/components/profile-workspace.tsx#L348) 固定在右侧。

建议窄屏改为用户摘要卡片或展开行，只保留「测试」主操作，其余放菜单；中等桌面宽度可将画像编辑移入抽屉，给表格留出空间。移动导航增加明确的更多入口/滑动提示，避免导航项隐藏在横向滚动中。

验收：390px 无需横向找寻即可看清完整用户 ID、关键标签并操作；1280px 设备和主要列不被固定操作列覆盖。

## 第二批可以改善

- **减少术语负担。** 广告主标识改为「广告主编号」并说明同一家填写相同编号；名称明确“用于展示”。发布提示用“已发布，约 5 秒内生效”，将 TTL、候选快照、Request/Campaign/Creative、ALL/ANY/NONE 等放到技术详情。主结果先展示计划名称和素材预览，ID 保留复制入口。
- **批量测试提供简单起点。** 初次页面同时出现种子、用户来源、并发、轮数、超时、时长、回传开关和空指标。保留现有高级能力，默认提供少量轮次的“体验模式”，高级参数折叠；不要默认引导新用户跑 1000 轮。已有载入演示功能可复用，不必再新增一套演示系统。
- **图表区分零与尚未发生。** “今天”按小时会把未来时段补零，计数坐标出现 0.25 或 0.75。未来时段可留空/弱化，曝光点击等计数轴使用整数；没有分母的比率考虑显示“—”，与实际 0% 区分。
- **诊断建议分清数据结论和探索建议。** 本次模型正确提醒小样本不足，但仍给出了放宽定向、增加素材等多项建议。优先展示“链路是否完整、数据是否足够”，把缺乏当前数据支持的优化建议降为可选探索，不将模型生成的 50–100 次等阈值当成已验证标准。

- 报表到 Agent 正确保留计划和时间，建议可以定位引用依据，并且没有自动修改计划。
- 已保存画像的标签显示、批量用户勾选中的中文设备/标签说明比只展示原始字段容易理解。

建议先解决两个 P1 与跨页上下文，再修通知和异步刷新，最后调整表格与技术详情。延续现有配色，不增加新的首页大横幅。本次完成体验与审查，未修改前端或业务实现；以上均为待改项。

## 实施结果（当日后续）

用户确认后完成以下修改，本节覆盖上文初次检查时的待改状态：

- 草稿创建后直接进入规则编辑；发布前提示缺少素材，发布后提供添加素材/试投入口。计划列表、筛选和投放中数量使用素材可用状态；不会改写数据库中的计划生命周期。

- 成功通知 4.5 秒后收起，切页或发布时清除旧通知；错误仍保留。回传/批量结束后即时刷新，并在 1/3/8 秒有限补刷，进入总览或计划页也刷新。报表跟随同步信号重新查询已应用的条件，不擅自提交用户未应用的筛选。
