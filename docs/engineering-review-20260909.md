## 范围与结论

本轮基于包含未提交改动的工作区，检查后端模块边界、重复实现、未使用代码、错误分类、并发恢复和项目检查入口。已有报表、投放诊断、性能工具等工作保留。用户确认另一个任务正在调整前端；本轮没有修改前端文件。

重点修复模型调用与广告计划错误处理的可复现问题，统一两处已有业务能力的实现。没有调整决策算法、结算事务、数据库连接池参数，也没有宣称吞吐或 GC 性能提升。

## 已修复的问题

| 优先级 | 触发与原行为 | 修复 |
| --- | --- | --- |
| P1 | 模型的并发请求 A 较慢，B 失败并打开熔断；A 随后成功，会把 B 刚打开的熔断关闭。旧请求失败也可能重新打开已经探测恢复的熔断。 | 为调用保存熔断代次，仅同代结果能改变状态；恢复和打开熔断时推进代次。 |
| P2 | 调用方取消请求会增加模型失败计数；已取消请求仍可能收到成功结果。取消半开探测后，需要再等一个完整熔断周期。 | 先检查调用方取消状态；取消不计入模型故障，丢弃迟到结果，释放半开探测名额。模型自身超时而调用方仍有效时，仍按模型失败处理。 |
| P2 | 投放诊断复制了规则生成的降级流程，但未对降级结果一致执行取消检查、错误分类和证据校验，也遗漏降级失败指标。 | 两类功能共用调用流程；诊断主模型和降级结果都进行证据校验，降级异常统一为不可用错误。 |
| P1 | 广告计划或素材操作发生数据库等未知错误时，返回 422 并直接暴露错误原文。 | 明确列出业务校验错误，保留其 422 提示；未知内部错误返回通用 500/campaign_failed，并在日志保留原因和 request_id。 |

位置：

- `internal/agentassistant/application/provider_execution.go`：共用调用、取消、降级、指标流程。
- `internal/agentassistant/application/resilient_provider.go`：熔断代次、半开探测与规则生成适配。
- `internal/agentassistant/application/resilient_diagnosis.go`：投放诊断适配与证据校验。
- `internal/campaign/adapter/http/handler.go`：业务错误与内部错误分流。
- `docs/openapi.yaml`：13 个计划/素材操作补充内部错误响应说明。

## 删除与复用

1. **删除未使用的对象池。** `internal/decision/application/pool.go` 中三个池及六个获取/归还函数没有任何外部调用。它不参与真实请求，没有已验证的优化收益；保留它会增加维护成本。相关当前说明已更新，历史实验报告保留原样。
2. **统一模拟身份规则。** 模拟投放和请求追踪此前分别维护相同的运行 ID 正则、用户 ID 正则和 1～100 范围检查。现在共用 `decision/domain.ValidateSimulationIdentity`，删除适配层重复正则及纯转发包装函数。HTTP 状态码、错误码和原有提示保持兼容。
3. **缩小诊断依赖。** `DiagnosisService` 改为依赖消费方定义的 `CampaignReader` 和 `CreativeReader`，仅包含查询所需的方法。原有内存/MySQL 仓库直接满足接口；未来测试替身或其他查询来源不必实现创建、保存等无关能力。
4. **共用 Agent 调用流程。** 草稿与诊断继续保留各自结果类型和校验，没有扩散成全项目通用的重试框架。新模型业务可在该模块内复用同一套故障处理。

## 工程检查入口

新增 `scripts/verify.ps1`：

~~~powershell
# Go 格式、vet、正式包测试，及前端 lint/回归测试
./scripts/verify.ps1

# 后端独立检查
./scripts/verify.ps1 -BackendOnly

# 有可用 C 编译器且 CGO_ENABLED=1 时启用竞态检测
./scripts/verify.ps1 -BackendOnly -Race
~~~

Makefile 与 CI 的 Go 包范围统一为 `./cmd/... ./internal/... ./tests/...`。格式检查补充 `tests/`。本地原来的 `go test ./...` 会把被 Git 忽略的 `work/` 实验包一并纳入，导致本地与干净 CI 的检查对象不同；新入口明确排除这些临时实验。

Linux/macOS 可使用 `make verify`。CI 原有前端格式检查、构建和 Go 竞态检测保留。

## 行为兼容与观测变化

- 草稿/诊断成功响应结构不变；草稿降级警告保留。
- 诊断未配置降级且熔断打开时，现在与草稿一致返回 `ErrProviderCircuitOpen`；HTTP 诊断接口仍按服务不可用返回 503。

## 后续建议

1. **按页面拆分前端主组件。** 审查时 `web/components/adflow-console.tsx` 已超过 2600 个非空行，混合计划、素材、单次决策、追踪与运营操作。建议由当前前端任务按页面组件和业务 Hook 拆分，优先拆清状态所有权与刷新依赖，不只把 JSX 搬到另一个文件。
2. **整理分页解析，但先固化兼容行为。** campaign、audit、operations、profiles 存在多套整数解析。默认页大小、limit=0 的处理、上下界和错误提示并不完全相同，不能直接替换成一套默认值。适合先建立端点契约用例，再抽取纯解析逻辑，把错误响应留在各适配层。
3. **补真实交互验证。** 部分前端回归测试使用读取源码和正则断言，能够约束代码形态，但无法证明组件实际渲染、交互和请求取消行为。拆组件时应补关键路径交互测试，保留已有纯函数用例。
4. **按证据继续优化热点。** 同步审计、事务提交和大报表读取应继续通过 profile/受控实验评估。本轮未把性能猜测变成代码参数调整，也未为减少重复而合并不同恢复语义的事务逻辑。
